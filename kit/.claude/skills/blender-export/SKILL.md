# Экспорт

## Формат под потребителя

| Куда | Формат | Почему |
|------|--------|--------|
| Веб, three.js, AR, быстрый обмен | **GLB** | PBR-материалы внутри одного файла, сжатый |
| Unity, Unreal, Maya | **FBX** | Иерархия, скиннинг, анимация |
| Универсальный обмен геометрией | **OBJ** | Читают все, но без анимации и без PBR |
| 3D-печать | **STL** | Только треугольники, ни материалов, ни UV |
| Доработка в Blender | **.blend** | Модификаторы, ноды, история — всё живое |

```python
export("out/model.glb")     # формат определяется по расширению
export("out/model.fbx", selected_only=True)
save("models/model.blend")
```

## Подготовка ДО экспорта — по потребителю

**Общее для всех:** `apply_transform()` (scale = 1), осмысленные имена, вычищенные
осиротевшие датаблоки (`purge()`).

**GLB / FBX (движок, веб):**
- Модификаторы применить (`apply_mods`) — subsurf в рантайме дорог.
- Полигонаж под бюджет: у subsurf снизить `render_levels` перед применением.
- UV обязательны для текстур: `smart_uv(obj)`.
- Ось вверх: glTF ждёт Y-up, экспортёр разворачивает сам — руками не крутить.

**STL (печать):**
- Модификаторы применить все — принтер видит только треугольники.
- Сетка замкнутая, нормали наружу.
- Масштаб в миллиметрах на выходе: в Blender модель в метрах, слайсер обычно
  читает STL как миллиметры — **проверить габарит и, если надо, отмасштабировать
  ×1000 перед экспортом**. Это самая частая ошибка при печати.
- Стенки не тоньше 1 мм в реальном размере.

**OBJ:** материалы уедут в отдельный `.mtl`, PBR при этом теряется — предупредить
владельца, а не отдавать молча.

## Godot 4 (проверено на персонаже v3, 18 сентября)

- Клипы — дорожками NLA, `export_animation_mode="NLA_TRACKS"`: каждая дорожка
  уходит отдельной анимацией, замьюченные тоже.
- Цикл — суффикс **`-loop`** в имени клипа (`walk-loop`): так его читает импорт Godot.
- Draco не включать: Godot 4 его не читает.
- Кость-сокет (`RightHandSocket`, `use_deform=False`) уходит в скин при
  `export_def_bones=False` — к ней в Godot цепляется `BoneAttachment3D`.
- 🔴 **`img.scale()` экспорт не видит:** с `export_image_format="AUTO"` в GLB
  ушёл упакованный исходный PNG 7.4 МБ. `"JPEG"` + `export_jpeg_quality=90`
  кодирует из текущих пикселей: 2048² — 0.6 МБ, GLB 9.5 → 2.7 МБ.
- Что реально ушло в файл — читать JSON-чанк GLB (длина — `uint32` по смещению
  12, JSON с байта 20) и делать повторный импорт в чистом Blender
  (`Blender -b --factory-startup --python …`), а не верить параметрам.

## Превью вместе с файлом

Отдавать не только модель, но и картинку — иначе владельцу надо открывать Blender,
чтобы понять, что пришло.

```python
setup_render("BLENDER_EEVEE", samples=48, res=(1400, 1050))
turntable("renders/<имя>", frames=4, elevation=22,
          distance=<габарит * 2.5>, target=<центр объекта>)
```

⛔ `distance=` и `target=` задавать руками: без них турнтейбл считает дистанцию
по всей сцене вместе с полом, и объект превращается в точку.

Готовые PNG показывать владельцу инструментом отправки файлов, а не только
упоминать пути.

## Куда складывать

- `models/` — `.blend` (исходник, всегда)
- `renders/<имя>/` — превью и турнтейбл
- `out/` — экспортные форматы под внешнего потребителя
