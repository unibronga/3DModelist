# Приёмка

Один проход перед сдачей. По ходу работы смотреть кадр после каждой правки —
это скил `blender-model`, не этот.
Разборы провалов — в `LESSONS.md` рядом.

## Объём — по классу ассета

Полный обряд на пропс в 800 трис — выброшенное время. Брать свою колонку:

| Шаг | Пропс, мебель | Интерьер, уровень |

## Команды

```bash
tools/bl -c 'result = scene_stats()'    # объекты, меши, трисы с модификаторами, материалы
tools/bl scripts/audit.py               # полный аудит сцены
```

`audit.py` ловит: неприменённый scale, n-gon'ы, дубли вершин, вывернутые нормали,
габариты вне разумного, имена `Cube.007`, объекты ниже пола, осиротевшие датаблоки.

## Два правила, которые ловят то, чего не видно на рендере

🔴 **Число, выбивающееся из масштаба сцены, — дефект, пока не доказано обратное.**
Габарит в десятки метров у ассета ростом 1.7 м, «мусорный» объект на 2 м,
полигонаж вшестеро выше тира. Такое не комментируют, такое проверяют.

🔴 **Смотреть вьюпорт в том виде, в каком его откроет владелец.** Рендер показывает
только то, что попало в кадр камеры; файл открывается целиком. Режим Material,
все объекты видимы, ничего не спрятано под диагностику, камера отведена на всю
сцену — и посмотреть глазами. Арматура, скрытые объекты и иерархия на рендере
не видны никогда.

```python
for o in bpy.data.objects:
    o.hide_set(False)
sp.overlay.show_face_orientation = False
sp.overlay.show_wireframes = False
sp.shading.type = 'MATERIAL'
with bpy.context.temp_override(window=w, area=a, region=region):
    bpy.ops.view3d.view_axis(type='FRONT')
    bpy.ops.view3d.view_all()
```

Снимать через официальный MCP: `get_screenshot_of_area_as_image` (обязательно с
`size_limit_in_bytes=400000`), навести — `jump_to_view3d_object_by_name`.

## Сходство с референсом

Лист `tools/bl scenes/<имя>.py --peek --ref <референс>` — референс первой
плиткой рядом с ракурсами модели. Сверять по контрольному листу скила
`blender-reference`: силуэт, палитра, плотность деталей, счёт элементов.

🔴 **Инструмент замера сам приводит сцену в нужное состояние** — живая сцена
копит состояние между прогонами (скрытые объекты, текущий кадр, активный
action); полагаться на то, что прошлый скрипт прибрал за собой, нельзя.

🔴 **Перед выводом «дефект» проверить единицы и границы данных.** Ложная тревога
стоит ровно столько же, сколько пропущенный дефект.

## Лечение типовых дефектов

```python
apply_transform(obj)                       # scale = 1,1,1
weld(obj, 0.0001)                          # склеить дубли вершин
select_only(obj); bpy.ops.object.mode_set(mode="EDIT")
bpy.ops.mesh.select_all(action="SELECT")
bpy.ops.mesh.normals_make_consistent(inside=False)
bpy.ops.mesh.quads_convert_to_tris()
bpy.ops.object.mode_set(mode="OBJECT")
purge()                                    # выгрести осиротевшие датаблоки
save("models/<имя>.blend")                 # всегда: рендер без исходника — половина работы
```

## Пороги полигонажа

Рендер-картинка — до ~2 млн трис. Игровой ассет — 5-50 тыс. на предмет, subsurf
применить. 3D-печать — замкнутая сетка, без вывернутых нормалей и внутренних
полостей, стенка ≥ 1 мм. Тиры проекта — `poly_budget(objs, tier)`, `POLY_TIERS`.

## Критик

Агент `blender-critic` получает пути к кадрам и референс, смотрит без знания
замысла, возвращает дефекты.

⚠️ Смотрит **кадры**, а не файл: риг, иерархию, масштаб, датаблоки он не увидит
по определению. Его «замечаний нет» не значит, что файл готов.
⚠️ Замечания **проверять**, а не принимать на веру: чинить непроверенное
замечание — ломать то, что работало.
