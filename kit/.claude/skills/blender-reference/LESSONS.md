# Разборы: чем оплачен порядок «стиль до постройки»

## Сундук Eltarax — 12+ итераций вместо 3

Модель строилась «вообще красиво», профиль подгонялся задним числом. Каждое
уточнение стиля владельцем разворачивало работу целиком: сначала фотореализм,
потом Warcraft, потом Death's Door. Три полных цикла там, где хватало одного.

**Причина не в модели, а в порядке действий.** Без зафиксированного профиля по
умолчанию включается фотореализм — таблицы roughness, микрофаски, асимметрия,
запечённые PBR-карты — и вся эта техника вредна, когда цель плоская стилизация.

**Копия вместо «в духе».** Трижды делал «правдоподобный сундук» вместо копии
референса: реалистичные пропорции вместо гипертрофии, натуральное дерево и
чёрная сталь вместо золота и светлой бежевой оковки. Каждый раз получалось
красиво и мимо.

**Счёт вместо впечатления.** Владелец заметил лишнюю дугу раньше меня, потому
что я сравнивал впечатление, а не считал элементы.

**Тяжёлый пайплайн для плоской стилизации.** Был выбран путь с запеканием — он
не нужен для flat вовсе. Отсюда правило: развилка пайплайна решается строкой
«Текстуры» в профиле, до первого кубика.

## Ловушки рисования текстуры кодом (`lib/paint.py`)

Все проверены на сундуке:

- хеш-шум на пиксель даёт «соль-перец» вместо фактуры — только плавные функции;
- зоны по координате обязаны учитывать **ориентацию грани**: `ax > W2 - CORNER`
  без проверки нормали красит всю боковину целиком;
- `inset_individual` на полукруглом торце вырождает вершины в бесконечность;
- `N` — нормаль грани, скаляр на треугольник: `N[2] > 0.4` нельзя совать в маску
  `[:, None]`, только в обычный `if`;
- **bump рисуется тем же художником**: карта высоты → `height_to_normal`. У границ
  UV-островов нормаль обязана быть плоской (`erode` маски покрытия), иначе
  градиент считается через шов и грани чернеют;
- 🔴 `colorspace_settings` менять строго **после** `image.save()`: у generated-
  изображения смена цветового пространства сбрасывает буфер в заливку, карта
  уезжает на диск чёрной, а модель выглядит обугленной.

## Запекание (архивный hand-painted пайплайн)

- `bpy.ops.wm.open_mainfile` изнутри скрипта рвёт контекст, и `object.bake` падает
  на `poll()`. Шаги гонять по живой сцене одной сессии моста.
- Искать `Principled BSDF` по имени ненадёжно — искать по типу `BSDF_PRINCIPLED`,
  материал собирать с нуля через `nodes.clear()`.
- Раздельный union дерева и металла с последующим DIFFERENCE оставляет внутренние
  стенки — невидимые грани, жрущие полигоны и место в UV.
- Нутро полой детали: сплошная вкладка-донор не работает, луч бьёт ей в изнанку.
  Нужна скорлупа из тех же констант, что и вырез (зазор ~1.5 мм).
- AO местами проваливается в ноль — при подмесе в альбедо это чёрные кляксы.
  Нижний порог 0.42 либо второй проход AO с самой сетки.
- WebP в glTF (`export_image_format="WEBP"`) режет GLB в 16 раз.
- 🔴 Blender **падает** на длинной цепочке тяжёлых шагов (замечено на экспорте GLB
  с запакованными картами 2048 + WebP). Процесс переподнимается сам с пустой
  сценой. Цепочку гонять пошагово с отдельным логом на шаг.


## Персонаж (25 сентября) — референс и планка

- **Референс задаёт владелец и не меняется.** Я заменил чиби-чарлист на
  картинку взрослого персонажа с сайта Tripo «чтобы дотянуть до планки» — владелец в
  ярости. Планка качества (скриншоты «вот такого уровня») — это требование к
  сетке, а не новая картинка.
- **Что нарисовано плоско, генератор вылепит плоско.** Глаза-наклейки и
  крошечные кисти на чарлисте → гладкое лицо и варежки. Прежде чем платить за
  прогон, сказать владельцу, чего на картинке не хватает для объёма.
- **Спека персонажа — с числами по силуэту**: доли роста, ширины по срезам,
  счёт пиков волос, заплат, дыр, палитра кластерами по окнам. Нарезка видов —
  порог по цвету фона, заливка внутренних карманов, отсев тени по оттенку.


## Лист из 41 предмета (26 сентября 2026)

- Спека по рядам с таблицей «№, предмет, Ш×Г×В, счёт, заметки» — 114 строк на
  41 предмет; ворота прошли за один показ. Хватило двух вопросов (остов,
  фактура).
- **Счёт с общего листа врёт**: по мелкой плитке насчитал бочке три обруча,
  ведру ушки, столбу 1.2 м — по увеличенному кусочку оказалось два обруча,
  приземистое ведро с рваным краем, столб 2.8 : 1, а «три столба» — связки
  жердей, якорь — обломок без кольца. Считать по кусочку 4× до записи в спеку.
- Нарезать лист на `rows/` и `items/` сразу: кусочек предмета идёт первой
  плиткой в `peek` каждого пропса, сверка по нему быстрее, чем по общему листу.
- Пропорция листа важнее моей догадки о размере: у столба и ведра размеры из
  спеки пришлось переписать под отношение высоты к ширине с картинки.
